# TASK-20261018-8c1 — Database Invalidation, Universal Key Transposition & Chord Token Validation
- **Tier:** 1
- **Date Created:** 2026-10-18
- **Status:** In Progress

---

## Feature Summary

Harden SQLite database asset synchronization, decouple musical key transposition so vocal pitch cues are available for all hymns (including lyrics-only Tagalog hymns), and enforce database integrity through musical chord token regex validation in unit tests.

Currently, pre-populated SQLite database files bundled in app assets can become stale on client devices if existing database files are not invalidated upon asset version updates. Additionally, key transposition controls are incorrectly bound to chord presence (`hasChords == 1`), depriving vocalists and accompanists of pitch-cue transposition on lyrics-only hymns. Finally, musical chord tokens in the database require automated regex verification to ensure no malformed chords enter the build artifact.

---

## Acceptance Criteria

1. **AC-1: Database Cache Invalidation by Version Stamp:**
   - Define a constant version stamp `kAppDbVersion` (or `kCurrentDbContentVersion`) in the database layer.
   - On database initialization in `AppDatabase`, inspect `SharedPreferences` for the stored content version.
   - If the stored version is missing or less than `kAppDbVersion`, invalidate and overwrite the existing local SQLite database copy with the asset database (`assets/db/hymns.db`), then update `SharedPreferences` with the new version stamp.
   - Subsequent launches with matching version stamps must open the existing database without overwriting user data.

2. **AC-2: Decoupled Key Transposition for All Hymns:**
   - In `SongControlsToolbar` and `ReaderScreen`, decouple the Key Transposition controls (semitone transpose +/- and key selector) from `song.hasChords == 1`.
   - Key transposition controls and the resulting tonic pitch cue must be visible and interactive for all songs, including Tagalog hymns and songs where `hasChords == 0`.
   - Chord-specific UI controls—specifically Capo selection, CAGED voicing diagrams, and the "Hide Chords" toggle—must remain strictly gated behind `song.hasChords == 1`.
   - Update summary text to show `'Key $soundingKey • Text Size ...'` when `hasChords == 0`.

3. **AC-3: Musical Chord Token Validation in Database Integrity Tests:**
   - In `test/data/database_integrity_test.dart`, add a test validating all chord tokens extracted from hymns where `hasChords == 1` or bracketed chord tokens are present.
   - Every extracted chord token must match the standard musical chord regular expression:
     `^[A-G](?:b|#)?(?:m|maj|min|dim|aug|sus|add)?[0-9]*(?:\/[A-G](?:b|#)?)?$`
   - Any malformed token (e.g. invalid root note, illegal modifiers, or corrupt characters) must fail the test suite with an informative message indicating song ID and invalid chord token.

## Out of Scope

- Modifying the underlying SQLite schema or table structure in Drift.
- Modifying audio playback engine or generating synthesized pitch cues.
- Adding chord charts or chord annotations to lyrics-only Tagalog hymns.
- Network-based remote database downloads or cloud sync.
